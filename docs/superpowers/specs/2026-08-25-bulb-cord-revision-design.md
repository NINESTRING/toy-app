## 0. 무엇을 바꾸는가

전구 기믹에서 두 가지를 바꾼다.

1. **토글이 릴리스로 간다.** 지금은 당기는 도중 임계값을 넘는 순간
   불·햅틱·카운트가 터진다. 앞으로는 임계값을 넘어본 상태에서 **손을 떼는
   순간** 터진다.
2. **줄이 로프가 된다.** 지금은 2차 베지에 1개라 한쪽으로밖에 못 휘어서,
   놓았을 때의 출렁임이 "휘었다 펴졌다"로 읽힌다. 마디 12개짜리 체인
   시뮬레이션으로 바꿔서 꼬리가 튀어오를 때 몸통이 뒤처지는 파형이
   나오게 한다.

## 1. 원본 스펙 §2를 뒤집는다

원본 §2는 릴리스 토글을 **명시적으로 기각**했다. 논거는 §0(지연)이었다:
릴리스를 기다리면 당김과 피드백 사이에 그만큼 지연이 낀다.

**그 결정을 뒤집는다.** 논거가 틀렸다기보다, 두 가지가 §0 손실을 상쇄한다.

- **원인이 한 점에 모인다.** 딸깍·불·카운트가 전부 손을 떼는 그 순간에
  같이 터진다. 임계값 통과는 손가락이 못 느끼는 사건이라 — 화면에 눈금이
  없다 — 당김 도중의 딸깍은 "왜 지금?"으로 읽힐 여지가 있었다. 릴리스는
  사용자가 스스로 만든 사건이므로 그 여지가 없다.
- **줄이 로프가 되면서 릴리스가 시각적 사건이 됐다.** 놓는 순간 줄이
  튀어오르므로, 그 순간에 불이 같이 켜지는 게 인과적으로 맞는다.

지연은 실재하지만 사용자가 릴리스 타이밍을 소유하므로 "느리다"가 아니라
"내가 놓아서 켜졌다"로 읽힌다. 이건 §0의 예외가 아니라 §0이 말하는
"입력과 피드백 사이"의 입력이 릴리스로 재정의된 것이다.

> 원본 §3 결정 표의 "임계값 통과 순간 토글" 행과 §5의 `onUpdate` 항목이
> 이 문서로 대체된다.

## 2. 토글 시점 — `_kinds/tug.tsx`

`fired`(이번 사이클에 이미 토글함)를 `armed`(이번 사이클에 임계값을
넘어봤음)로 바꾼다.

| 콜백 | 지금 | 개정 |
|---|---|---|
| `onUpdate` | 임계값 통과 → `on` 토글 + 햅틱 + `onInteract` + `fired` | 임계값 통과 → `armed = true`. **아무것도 안 터진다** |
| `onFinalize` | `fired` 해제, 스프링 복귀 | `armed`면 `on` 토글 + 햅틱 + `onInteract`. 그 뒤 `armed` 해제, 스프링 복귀 |

**햅틱도 릴리스로 간다.** 딸깍과 불이 시간적으로 갈라지면 "장전됐다"는
신호가 손에만 먼저 오는 어중간한 상태가 된다. 프리셋은 `latch` 그대로 —
여전히 실기기 미검증이다(원본 §10).

### 한 번 걸리면 안 풀린다

`armed`는 임계값을 넘는 순간 서고, **그 뒤 손가락이 휴지점으로 되돌아와도
내려가지 않는다.** 100pt 당겼다가 제자리에 놓아도 토글된다.

레퍼런스 펜은 릴리스 **시점의** 거리로 재므로 이 경우 불발이다. 우리가
갈라지는 이유:

- 실제 걸쇠는 트립하면 되돌릴 수 없다. `latch` 프리셋을 고른 것과 같은 모델이다.
- 피젯 토이에서 제일 나쁜 실패는 "다 당겼는데 안 켜졌네"다. 관대한 쪽이 옳다.

### 줄이 늘어져 있으면 불발 (2026-08-25 추가)

`armed`가 서 있어도 **릴리스 순간 줄이 원래 길이보다 짧으면 쏘지 않는다.**
줄이 늘어졌다는 건 매듭을 위로 밀어 올린 상태라는 뜻이고, 실제 풀체인
스위치는 밀어서는 안 걸린다 — 당겨야 걸린다.

판정은 앵커→매듭의 **현 길이**로 한다. 휴지점이 앵커 바로 아래 `SPAN`(146pt)에
있으므로 현은 `hypot(dragX, SPAN + dragY)`이고, 이게 `SPAN` 미만이면 불발이다.
휴지점 자체(현 = SPAN)는 발화 쪽이다.

옆으로만 당기는 것은 현을 늘리므로 발화한다(60pt 옆 → 현 157.8pt). 위로 밀되
옆으로 크게 당긴 경우도 현이 길어지면 발화한다 — 방향이 아니라 **길이**가
기준이다. 매듭을 앵커 위로 지나쳐 밀면 현이 오히려 더 짧아지므로 여전히 불발이다.

**기하는 `cordPhysics.ts`가 갖고 `_kinds/tug.tsx`는 모른다.** tug의 임계값은
"얼마나 당겼나"만 보므로 이 판정을 스스로 못 한다. 그래서 tug에 선택적
`canFire?: (dragX, dragY) => boolean` 워크릿 prop을 두고, 전구가
`isCordTaut`을 넘긴다. `_kinds`가 기믹의 도형을 모른다는 §4의 역할 분담을
유지하려는 것이다 — `TugConfig`에 span을 넣었으면 146이 두 군데로 갈라진다.

거부되면 `armed`는 그냥 풀린다. 장전을 남겨두면 다음에 손만 대도 터진다.

### 안 바뀌는 것

거리는 **잡은 지점 기준**(`event.translationX/Y`)으로 잰다. 원본 §5의
정정 사유 — 복귀 스프링 도중의 줄(이미 임계값 밖)을 다시 잡았을 때 1px만
움직여도 재토글되는 구멍 — 이 릴리스 토글에서도 그대로 유효하다.

`threshold` 60pt도 그대로. 다만 의미가 "넘는 순간 딸깍"에서 "이만큼
넘겨야 인정"으로 바뀌면서 체감이 더 관대해진다.

`onFinalize`는 취소에도 불린다. 취소도 릴리스로 친다 — 펜과 같다.

### 사이클당 1회

릴리스가 사이클을 끝내므로 "한 번의 당김에 토글 1회"는 이제 구조적으로
보장된다. 별도 가드가 필요 없다.

## 3. 줄 물리 — `src/gimmicks/bulb/cord.ts` (신규)

### 경계

**tug는 매듭 변위만 준다. 줄 모양은 bulb가 소유한다.** 지금 계약
(`TugRenderState`)이 그대로 유지된다 — 복귀 스프링도 `_kinds/tug.tsx`에
그대로 남는다. 로프는 그 위에 얹히는 **생김새**다.

- 마디 0 — 캡 바닥(`CORD_ANCHOR`)에 고정
- 마디 11 — 매듭(`CORD_REST + drag`, 즉 tug 스프링)에 고정
- 마디 1~10 — 자유. 중력 + 거리 제약

꼬리가 스프링으로 튀어오르면 몸통이 관성으로 뒤처지고, 제약이 그걸 따라
끌면서 파형이 저절로 생긴다. 사진의 S자가 이거다.

세게 당겨 매듭이 로프 길이 밖으로 나가면 제약이 중간 마디를 직선으로
편다 — 팽팽해진다. 예외 처리 없이 나온다.

### 적분 (PBD)

퍼퍼 색종이(`popper/confetti.tsx`)의 프레임콜백 전례를 그대로 따른다:
`useSharedValue<Node[]>` + 제자리 변형 + `tick` 공유값으로 파생값 깨우기,
`Math.min(dtMs, 64)` 클램프.

마디 하나는 `{ x, y, px, py, vx, vy }`. 매 프레임:

1. **적분** — 자유 마디에 `v *= max(0, 1 - DRAG*dt)`, `vy += GRAVITY*dt`.
   직전 위치를 `px, py`에 저장하고 `p += v*dt`.
2. **핀** — 마디 0을 앵커에, 마디 11을 `CORD_REST + drag`에 박는다.
3. **거리 제약 5회 반복** — 이웃 쌍의 거리가 `SEGMENT_LEN`을 **넘을 때만**
   당긴다. 로프지 막대가 아니다. 양쪽이 다 자유면 반씩, 한쪽이 핀이면
   자유인 쪽이 전부 움직인다.
4. **속도 회수** — `v = (p - p_prev) / dt`. 제약이 위치를 옮긴 만큼이
   속도에 반영된다. 가변 dt에서 안전한 표준 PBD 형태다.

### 왜 당기기 전용 제약인가

양방향(막대)으로 하면 여유 길이가 있는 수직 줄이 압축에 저항하면서
좌우 어느 쪽으로 좌굴할지 수치 오차가 정하게 된다 — 쉴 때 미세하게
떨린다. 당기기 전용이면 여유분은 그냥 아래로 처진다.

여유는 2%(`CORD_SLACK = 1.02`)다. 앵커와 휴지점이 수직으로 146pt
떨어져 있고 로프 길이가 148.9pt이므로, 쉴 때 매듭보다 약 1.5pt 아래로
처졌다가 올라온다. 스무딩 곡선에 묻힌다.

### 경로

마디들을 지나는 2차 베지에 체인 — 각 마디를 제어점으로, 이웃 마디와의
중점을 끝점으로 삼는 표준 중점 스무딩이다. 마디가 12개, 세그먼트가
13.5pt라 꺾임은 눈에 안 띈다.

경로 생성은 지금처럼 `useDerivedValue` 안에서 한다(원본 §6의 논거 그대로 —
줄은 형태 자체가 프레임마다 바뀌므로 미리 못 만든다). 배열 제자리 변형은
파생값을 안 깨우므로 프레임 콜백이 `tick`을 올린다 — 퍼퍼와 같다.

### 놀 때 비용 0

세 조건이 다 참이면 `asleep`을 세우고 프레임 콜백이 일찍 반환한다:

- 드래그 중이 아님 (`!active`)
- 매듭이 휴지점 (`|dragX|, |dragY| < 0.25`)
- 모든 자유 마디 속도 < `SLEEP_SPEED`

깨우는 건 `active`에 건 `useAnimatedReaction` 하나다. 잠든 뒤 매듭이
움직이려면 새 제스처가 있어야 하고, 그건 `active`를 세운다.

### 훅은 Canvas 바깥에서

`useCord`는 `BulbBody`에서 부른다. Skia는 `Canvas`의 자식을 별도
react-reconciler 루트에 마운트하므로 Canvas 안에서 훅을 부르면 RN 트리가
아닌 그 루트의 생명주기를 탄다 — 퍼퍼가 `useConfetti`/`ConfettiAtlas`를
나눈 이유와 같다.

`useCord({ dragX, dragY, active })` → `{ path, knotX, knotY }`.

### 스프링도 같이 조정

`WHIP_SPRING`의 damping을 9 → 12로 올린다. 출렁임을 이제 줄이 담당하므로
매듭까지 통통 튀면 두 겹이 된다. 매듭은 깔끔하게 돌아오고 파형은 줄이 문다.

> ⚠️ 물리 상수 전부 실기기 미검증이다 — `GRAVITY`, `DRAG`, `CORD_SLACK`,
> `WHIP_SPRING`, 반복 횟수. 퍼퍼·다이얼과 같은 상태다.

## 4. 상수

| 이름 | 값 | 비고 |
|---|---|---|
| `NODE_COUNT` | 12 | 세그먼트 11개. 늘리면 오히려 더 접힌다 — §4.4 |
| `CORD_SLACK` | 1.0 | 쉴 때 정확히 팽팽 — §4.2 |
| `SEGMENT_LEN` | ≈13.3 | `146 / 11` |
| `GRAVITY` | 2200 pt/s² | |
| `DRAG` | 2.6 /s | |
| `CONSTRAINT_ITERATIONS` | 8 | |
| `BUCKLE` | 50000 pt/s² | 좌굴 씨앗 — §4.1 |
| `BUCKLE_REF_SPEED` | 600 pt/s | 좌굴력이 최대가 되는 매듭 속력 — §4.1 |
| `BEND_MIN` | 0.85 | 굽힘 강성 — §4.3 |
| `SLEEP_SPEED` | 1.5 pt/s | |
| `WHIP_SPRING.damping` | 9 → 12 | |

구현하면서 스펙에 없던 메커니즘 3개가 필요해졌다. 아래가 그 기록이다.

### 4.1 좌굴 씨앗 (`BUCKLE`, `BUCKLE_REF_SPEED`) — 없으면 S자가 안 나온다

앵커·휴지점·중력이 전부 x=150 위에 있다. 그래서 수직으로 당겼다 놓으면
**완벽히 대칭인 좌굴 문제**가 되고, 여유분이 어느 쪽으로도 안 휘고 제자리에서
수직으로 접힌다 — 줄이 자기 위로 겹쳐 보인다. 실제 줄은 굽힘 강성과 미세한
비대칭 때문에 반드시 한쪽으로 휜다. `BUCKLE`이 그 비대칭의 대역이다.

문이 두 개다. **접힌 정도**(팽팽하면 0)와 **매듭 속력**(`BUCKLE_REF_SPEED`).
접힌 정도만으로 열면 안 된다 — PBD는 반복이 유한해서 쉴 때도 구간마다 몇 %씩
접혀 있고, 그게 새면 좌굴력이 영구히 살아서 줄이 한쪽으로 기운 채 굳는다
(실측 최대 10pt). 매듭 속력은 쉴 때 정확히 0이라 그 구멍이 없고, 물리적으로도
채찍 에너지는 꼬리가 넣는 것이라 이쪽이 맞다.

### 4.2 여유는 상수가 아니라 오버슈트가 만든다 (`CORD_SLACK` 1.0)

S자는 앵커→매듭 **현이 로프보다 짧아질 때만** 나온다. 팽팽하면 정의상 직선이다.

처음엔 상시 여유(1.02)를 주려 했는데 그러면 쉴 때도 좌굴력이 새어나간다.
필요한 여유는 상수가 아니라 **릴리스 스프링이 매듭을 앵커 쪽으로
오버슈트시키면서** 만들어진다 — damping 12 / stiffness 300이면 아래로 90pt
당긴 뒤 위로 28pt까지 넘어가고, 그때 현이 로프보다 26pt 짧아진다. 그 여유분이
접힌다.

> 그래서 **수평으로만 흔들면 S자가 안 나온다.** 현 길이가 로프와 같게 유지돼서
> 곡선이 펴진 채로 남는다. 풀코드의 실제 제스처가 수직 당김이라 문제되지
> 않지만, 검증할 때 이걸 몰라서 한참 헤맸다.

### 4.3 굽힘 강성 (`BEND_MIN`) — 원래 범위 밖이었다

좌굴력만 넣으면 힘이 앵커 근처 한 마디에 몰려 줄이 거의 반으로 접힌다
(최소 내각 **3.9도**). 한 칸 건너 마디 (i, i+2)를 `BEND_MIN × 2세그먼트`보다
가깝게 두지 않는 **밀어내기 전용** 제약을 넣으면 휘어짐이 길이 전체로 퍼진다
(내각 **99.9도**).

원본 계획은 이걸 "실기기에서 보이면 그때"로 미뤘는데 시뮬레이터에서 이미
보였으므로 지금 넣었다.

### 4.4 마디를 늘리면 더 나빠진다

같은 반복 횟수에서 마디를 늘리면 반복당 수렴이 나빠지고 세그먼트가 짧아져서
오히려 더 접힌다. 실측 최소 내각: 12개 99.9도, 16개 85.0도, 20개 68.3도,
26개 78.3도. **12개가 최적이다.**

## 5. 범위 밖

- **쉴 때 물결치는 줄** — 사진의 S자는 출렁이는 중의 한 프레임이다.
  쉴 때는 지금처럼 수직이다.
- 원본 §7의 범위 밖 항목(사운드, 장력 햅틱, 켜짐/꺼짐 파형 분리,
  전구 본체 기울임)은 전부 그대로 범위 밖이다.

## 7. 검증

| 확인할 것 | 방법 | 가능 여부 |
|---|---|---|
| 타입 | `npm run typecheck` | 가능 |
| **적분기 수치 검증** | `cordPhysics.ts`를 Node로 직접 실행 | 가능 — 아래 참조 |
| 쉴 때 레이아웃 (줄이 수직인지) | `npm run ios:sim` + 스크린샷 | 가능 |
| 켜짐 상태 색 | 임시 Redirect로 강제 `on=1` + 스크린샷 | 가능 |
| **출렁임 파형(렌더)** | 임시 필름스트립 화면 + 스크린샷 | 가능 — 아래 참조 |
| `isCordTaut` 경계 | Node 하니스 11케이스 | 가능 |
| **릴리스 토글 손맛, 물리 상수의 적정값** | 실기기 | **불가 — 미검증으로 넘김** |

시뮬레이터는 터치를 못 넣는다 — 손맛은 실기기 항목이다.

**적분기는 실기기 없이 검증한다.** `cordPhysics.ts`에 import를 하나도 두지
않으면 Node가 타입만 벗겨내고 바로 실행할 수 있다(`--experimental-strip-types`,
Node 24 기본값). 이 앱엔 테스트 러너가 없으므로 이게 유일한 자동 검증 수단이다.
확인 항목: 쉴 때 수직으로 수렴하는지, 매듭을 로프 길이 밖으로 끌면 직선으로
펴지는지, 매듭이 스프링으로 왕복할 때 수직선 기준 부호 변화가 2번 이상
생기는지(= 사진의 S자), 1000프레임 동안 NaN이 안 나는지.

하니스는 스크래치패드에 두고 커밋하지 않는다 — 러너가 없어 CI에서 돌 곳이
없고, 리포에 실행되지 않는 테스트를 남기는 건 거짓 신호다.

**렌더까지 눈으로 본다.** 마디 좌표가 S자인 것과 화면에 S자가 그려지는 것은
다른 얘기다(중점 스무딩이 파형을 뭉갤 수 있다). 시뮬레이터엔 터치를 못 넣고
`simctl` 스크린샷은 1초쯤 걸려서 300ms짜리 되튐을 못 잡으므로, **임시 화면을
하나 만들어 되튐의 여러 프레임을 한 화면에 필름스트립으로 펼쳐 그렸다** —
실제 `stepCord`, 실제 경로 빌더, 실제 Skia다. 이 방법으로 §4.3의 접힘을
찾았다. 확인이 끝나면 임시 화면은 지운다.

> 하니스의 "날카로운 꺾임" 문턱은 처음 120도로 잡았는데, 굽힘 강성을 넣은 뒤
> 최소 내각이 100도쯤에서 평평해지고 그 상태의 필름스트립이 육안으로
> 매끄러웠다. 세그먼트가 13pt로 짧고 중점 스무딩이 각을 굴린다. **문턱이
> 렌더와 안 맞았던 것이므로 85도로 조정했다** — 병리적 접힘(3.9도)은 여전히
> 잡힌다.
